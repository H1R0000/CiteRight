# Security reporting

Security fixes target the latest version on the repository's default branch. No older release has a separate maintenance commitment.

Do not disclose exploitable vulnerabilities or sensitive data in public issues. If this repository's Security tab offers “Report a vulnerability,” use that private reporting channel. If it is unavailable, open a public issue requesting a private contact without including exploit details, credentials, or user data.

Include affected versions, impact, and minimal reproduction steps through the agreed private channel. No response-time guarantee is offered.

Maintainer release checklist: enable GitHub private vulnerability reporting and verify the reporting route before public launch.
